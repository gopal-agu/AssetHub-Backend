# AssetHub Backend (ASP.NET Core 8 Web API)

Backend for the **AssetHub-frontend** React app (IT asset lifecycle management: inventory intake,
assets, assignment/transfer, maintenance tickets, vendors, employees, categories, dashboard).

Built to replace the frontend's in-memory `DataContext.jsx` / `mockData.js` 1:1 — same entities, same
id formats (`AST-LAP-00047`, `EMP-1042`, `VEN-118`, `GRN-2026-000012`, `MT-2026-00231`, `CAT-101`),
same status values, same field names (camelCase JSON) — so wiring the frontend to it is a matter of
swapping `useData()` calls for `fetch`/`axios` calls, not reshaping data.

## Architecture

Clean/layered architecture, 3 projects:

```
src/
  AssetHub.Core             Domain layer — no dependencies on anything else
    Entities/                EF entities (Category, Vendor, Employee, InventoryBatch, InventoryItem,
                              Asset, AssignmentHistory, MaintenanceRecord, ActivityLog, Sequence, User)
    Dtos/                    Request/response DTOs per feature (Auth, Category, Vendor, Employee,
                              Inventory, Asset, Maintenance, Dashboard)
    Interfaces/
      Repositories/           IGenericRepository<T>, IUnitOfWork, IAssetRepository, IInventoryBatchRepository
      Services/                One interface per business service
    Common/                  AssetStatuses/MaintenanceStatuses/etc. constants, ApiException, PagedResult

  AssetHub.Infrastructure   Data access + business logic implementation
    Data/                    AppDbContext, EF Fluent configurations, DbSeeder (ports mockData.js)
    Repositories/            GenericRepository<T> (generic repository pattern) + UnitOfWork +
                              AssetRepository/InventoryBatchRepository (the few queries needing .Include())
    Services/                CategoryService, VendorService, EmployeeService, InventoryService,
                              AssetService, MaintenanceService, DashboardService, AuthService,
                              JwtTokenService, SequenceService, ActivityLogService

  AssetHub.API               Presentation layer
    Controllers/              AuthController, CategoriesController, VendorsController,
                               EmployeesController, InventoryController, AssetsController,
                               AssignmentHistoryController, MaintenanceController, DashboardController
    Middleware/               ExceptionHandlingMiddleware (ApiException -> proper status code + JSON body)
    Program.cs                DI, JWT auth, CORS, Swagger, seeding
```

**Generic repository + Unit of Work**: `IGenericRepository<T>` gives every aggregate CRUD + query
plumbing for free; `IUnitOfWork` exposes one repository per aggregate plus the two repositories that
need custom `.Include()` queries (`IAssetRepository`, `IInventoryBatchRepository`), and commits
everything through a single `SaveChangesAsync()` so multi-table operations (e.g. assigning an asset
also writes an `AssignmentHistory` row) are atomic.

**DTOs**: controllers and services never expose EF entities directly — every endpoint has its own
request DTO (`CreateXDto`, `UpdateXDto`, action DTOs like `AssignAssetDto`) and response DTO (`XDto`),
mapped by hand inside each service (private `Map(...)` method) for full control over the exact JSON
shape the frontend already expects.

**Ids**: generated by `SequenceService`, a DB-backed counter table (`Sequences`) that reproduces the
frontend's `utils/idGenerator.js` formats exactly, so codes stay unique across restarts/instances
instead of living in `localStorage`.

## Entity ↔ frontend mapping

| Backend entity      | Frontend source                              | Id format          |
|----------------------|-----------------------------------------------|---------------------|
| `Category`            | `data/categoryConfig.js`, Categories.jsx      | `CAT-101`            |
| `Vendor`               | `mockData.js` VENDOR_SEED, Vendors.jsx        | `VEN-118`            |
| `Employee`             | `mockData.js`, Employees.jsx                  | `EMP-1042`           |
| `InventoryBatch` + `InventoryItem` | Inventory.jsx / `addInventoryBatch` | `GRN-2026-000012`    |
| `Asset`                | `mockData.js` BATCH_PLAN, Assets.jsx          | `AST-LAP-00047`      |
| `AssignmentHistory`    | assign/unassign/transfer actions              | `{assetId}-A1/-R1/-T1` |
| `MaintenanceRecord`    | raiseMaintenance/closeMaintenance             | `MT-2026-00231`      |
| `ActivityLog`          | `activityLog` feed on Dashboard               | numeric              |

## API surface

All endpoints except `/api/auth/login` require `Authorization: Bearer <token>`.

| Method & route                          | Frontend action it replaces                         |
|------------------------------------------|--------------------------------------------------------|
| `POST /api/auth/login`                    | `AuthContext.login()`                                   |
| `GET /api/categories`, `GET /{id}`        | `categories` list                                        |
| `POST /api/categories`                    | `addCategory()`                                          |
| `PUT /api/categories/{id}`                | `updateCategory()`                                       |
| `GET /api/vendors`, `GET /{id}`           | `vendors` list                                            |
| `POST /api/vendors`                       | `addVendor()`                                             |
| `GET /api/employees`, `GET /{id}`         | `employees` list                                          |
| `POST /api/employees`                     | `addEmployee()`                                            |
| `GET /api/inventory`, `GET /{id}`         | `inventoryBatches` list                                    |
| `POST /api/inventory`                     | `addInventoryBatch()` (+ auto asset generation)            |
| `PUT /api/inventory/{id}`                 | `updateInventoryBatch()`                                    |
| `GET /api/assets?category=&status=&location=&department=` | `assets` list (with filters)           |
| `GET /api/assets/{id}`                    | single asset detail (AssetDetailDrawer.jsx)                 |
| `POST /api/assets`                        | manual asset creation                                        |
| `PUT /api/assets/{id}`                    | `updateAsset()`                                               |
| `POST /api/assets/{id}/assign`            | `assignAsset()`                                                |
| `POST /api/assets/{id}/unassign`          | `unassignAsset()`                                                |
| `POST /api/assets/{id}/transfer`          | `transferAsset()`                                                 |
| `POST /api/assets/{id}/status`            | `changeAssetStatus()`                                              |
| `POST /api/assets/{id}/retire`            | `retireAsset()`                                                     |
| `GET /api/assets/{id}/history`            | per-asset assignment history                                          |
| `GET /api/assignmenthistory`              | `assignmentHistory` list (Reports.jsx)                                  |
| `GET /api/maintenance?assetId=&status=`   | `maintenanceRecords` list                                                |
| `POST /api/maintenance`                   | `raiseMaintenance()`                                                       |
| `POST /api/maintenance/{id}/close`        | `closeMaintenance()`                                                        |
| `GET /api/dashboard/summary`              | all of Dashboard.jsx's derived stats + `activityLog`                         |

Reports.jsx does its filtering/exporting entirely client-side from `assets`, `employees`, `vendors`,
`inventoryBatches`, `assignmentHistory` and `maintenanceRecords` — the list endpoints above already
supply all of that, so no separate reporting endpoints were needed.

## Running it

### 1. Prerequisites
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- SQL Server (local, Docker, or Azure SQL) **or** just use the in-memory DB for a zero-setup demo (see below)

### 2. Restore & build
```bash
cd AssetHub.Backend
dotnet restore
dotnet build
```

### 3. Choose a database

**Option A — zero setup (in-memory DB, data resets on every restart)**
Already the default in `appsettings.Development.json` (`"UseInMemoryDb": true`). Just run:
```bash
dotnet run --project src/AssetHub.API
```

**Option B — SQL Server (persistent)**
1. Set `"UseInMemoryDb": false` in `appsettings.json` (or `appsettings.Development.json`).
2. Update `ConnectionStrings:DefaultConnection` in `appsettings.json` with your SQL Server details.
3. Create the initial migration and database:
   ```bash
   dotnet tool install --global dotnet-ef   # once, if not already installed
   cd src/AssetHub.API
   dotnet ef migrations add InitialCreate --project ../AssetHub.Infrastructure --startup-project .
   dotnet ef database update --project ../AssetHub.Infrastructure --startup-project .
   ```
4. Run:
   ```bash
   dotnet run
   ```

Either way, the API seeds itself on first run (`DbSeeder`) with the same vendors/employees/asset mix
the frontend's `mockData.js` ships, plus two login accounts:

| Email                     | Password     | Role           |
|-----------------------------|---------------|------------------|
| `admin@assethub.io`          | `Admin@123`    | Administrator     |
| `itmanager@assethub.io`      | `Manager@123`  | IT Manager         |

### 4. Try it
- Swagger UI: `http://localhost:5100/swagger`
- Or open `src/AssetHub.API/AssetHub.API.http` in VS Code / Rider / Visual Studio and run the requests.

### 5. Point the frontend at it
In the React app, replace the `AuthContext`/`DataContext` mock logic with calls to this API's base
URL (`http://localhost:5100/api`), storing the JWT from `/api/auth/login` and sending it as
`Authorization: Bearer <token>` on every other call. Update CORS `Cors:AllowedOrigins` in
`appsettings.json` if the frontend runs on a different port than `http://localhost:5173`.

## Security notes before deploying
- Replace `Jwt:Secret` in `appsettings.json` with a long random value kept out of source control
  (user secrets / environment variable / key vault).
- Set `UseInMemoryDb` to `false` and point `DefaultConnection` at a real SQL Server instance.
- Tighten `Cors:AllowedOrigins` to your real frontend origin(s).
